## 使用对象

除基本类型外，Java中的对象都是通过**引用**（reference）来操作。例如，下面示例中的  `person` 标识符实际上就是一个引用，它指向位于堆中的实际对象。

```java
Person person = new Person("AnnoRuo", 18);
```



通过`class`关键字来定义一个**类**：

```java
class ClassName { }
```

通过`new`关键字创建该类的对象

```java
ClassName a = new ClassName();
```

当定义一个类时，你可以为其定义两种成员：**字段**（数据成员）和**方法**（成员函数）。按照它们归属于实例还是类本身，可分为**实例成员**（非静态）和**静态成员**。

## 构造器

构造器的语法规则：

1. 构造器的名称必须与类名相同
2. 一个类可以拥有多个构造器
3. 构造器可以包含任意个参数
4. 构造器没有返回值
5. 构造器始终由 new 运算符进行调用
6. 构造器本质上是一个静态方法

### 默认构造器

不带参数的构造器称为**默认构造器（default consttructor）或者称为无参构造器（no-arg constructor）**。当你未显式创建任何构造器时，编译器会为你创建一个隐式的无参构造器。

## this

每个对象方法（除 static 方法）都有一个隐藏参数 this，位于所有显式参数之前，代表着被操作对象的引用。

```java
Banana a = new Banana()
Banana b = new Banana();

// 代码表现形式：
a.peel(1);
b.peel(1);

// 编译后的内部表现形式为：
Banana.peel(a, 1);
Banana.peel(b, 1);
```

如果你想在一个方法里获得对当前对象的引用，那么就使用 this 关键字：

```java
Banana getBanana() {
	return this;
}
```

>不必在每个实例字段引用和实例方法调用前都加 `this.`。现代 IDE 的语法高亮已经能很好地区分成员与局部变量，过度使用反而会增加视觉噪音。但在消除歧义（如参数与字段同名）、构造器重载以及链式调用等场景中，`this` 是表达意图的重要工具。

## 清理对象

### 垃圾收集器

Java 的**垃圾收集器**（Garbage Collector）会自动回收不再使用的对象内存。但需要注意，GC 只管理 JVM 堆上的对象内存，对于对象持有的非内存资源无能为力，例如：

- 本地方法中通过 `malloc` 分配的原生内存
- 文件句柄、Socket 等系统资源

这些资源必须由程序员手动释放。

为此，Java 在 `Object` 类中提供了 `finalize()` 方法，子类可以重写它。GC 在回收对象前可能会调用该方法，但调用时机完全不可预测，甚至可能永远不会被调用。因此，`finalize()` 绝不等于 C++ 的析构函数——后者在对象销毁时必定执行，而前者毫无保证。

最佳实践：始终通过显式方法释放资源，惯用命名如 `close()`、`dispose()`、`clean()` 等，将清理责任明确交给程序员。

>⚠️ 注意：`finalize()` 已在 Java 9 中被标记为废弃（@Deprecated），并在 Java 18 中彻底移除。

## static

static 关键字主要解决以下两类需求：

- **共享数据**：某个字段需要在所有对象间共享，且不依赖于任何对象是否存在
- **独立行为**：某个方法不依赖于对象状态，即使未创建实例也能直接通过类名调用

static 成员是基于类创建的，而实例成员是基于对象创建的。静态方法不持有任何对象引用，因此无法在其中直接访问实例字段、实例方法，也无法使用 `this` 关键字。然后在实例方法中则可以自由地访问静态成员。



>从设计范式上看，静态方法具有全局函数的语义，这也是一些人认为它不符合纯面向对象思想的原因。至于这是否是"正确的 OOP"，不妨留给理论家去争论。

## final

### 数据 final

常量可以分为：

- **编译时常量**：对编译时常量来说，编译器可以将常量值「折叠」到计算中。这节省了一些运行时开销。
- **运行时常量**：运行时常量允许延迟初始化。对于基本类型，它的值不变；一旦引用被初始化为一个对象，它就永远不能被更改为指向另一个对象了。但是，对象本身是可以修改的。总而言之，final 确保栈上的值保持不变

### 方法 final

使用 final 方法的原因有两个：

- OOP 设计：禁止子类通过重写（Override）改变其语义

- 性能优化：

  - **消除动态绑定**：由于 `final` 方法不可被重写，编译器在编译期就能确定调用目标，无需通过虚方法表进行运行时动态分派。这让编译器可以为 final 方法的调用生成更为高效的代码。

  - **方法内联**：编译器直接将对 `final` 方法的调用替换为方法体中实际代码，省去参数压入栈，跳到方法代码处并执行，跳回并清除栈上的参数等调用开销。但这会让代码膨胀。

    >现代编译器已经足够智能，可自行判断是否需要执行方法内联优化，绝大多数情况下不会采纳 `final` 的内联优化提示。因此最好仅将 final 用作设计决策，而不是尝试用它提高性能。长期以来，Java 官方并不鼓励使用 final 来进行性能优化。

此外，类中的任何 private 方法都是隐式的 final。

### 类 final

将整个类定义为 final 时，就阻止了该类的所有继承，此时它的所有方法都是隐式 final 的。
