## 使用对象

Java 中的对象都是通过**引用**（reference）来操作。例如，下面示例中的  `person` 标识符实际上就是一个引用，它指向位于堆中的实际对象。

```java
Person person = new Person("AnnoRuo", 18);
```



通过`class`关键字来定义一个**类**：

```java
class ClassName { }
```

通过`new`关键字创建该类的对象

```java
ClassName a = new ClassName();
```

当定义一个类时，可以为其定义两类成员：**字段**（数据成员）和**方法**（成员函数）。按照它们归属于实例还是类本身，可分为**实例成员**和**静态成员**。

## 构造器

构造器的语法规则：

1. 构造器的名称必须与类名相同
2. 一个类可以拥有多个构造器
3. 构造器可以包含任意个参数
4. 构造器没有返回值
5. 构造器始终由 new 运算符进行调用
6. 构造器本质上是一个静态方法

### 默认构造器

不带参数的构造器称为**默认构造器（default consttructor）或者称为无参构造器（no-arg constructor）**。当你未显式创建任何构造器时，编译器会为你创建一个隐式的无参构造器。

### this 构造器调用

```java
class Phone {
  String model;
  Phone(String model) { this.model = model; }
  Phone() { this("Android"); }
  Phone() { this("Android"); this("iOS"); }	// 错误，不能同时调用两个构造器
  Phone() { model = ""; this("iOS"); }	    // 错误，this() 必须是第一条语句
  void f() { this("Android"); }			   // 错误，不能在非构造器中使用
}
```

在 Java 25 之前，显式构造器调用（`this(...)` 或 `super(...)`）必须是构造器体内的第一条语句。Java 25 通过 JEP 513 正式移除了这一限制，允许在构造器调用前编写语句。构造器调用之前的这一阶段称为**早期构造上下文**（early construction context）。

在早期构造上下文中，不得访问正在构造的实例（the instance under construction）。具体禁止的操作包括：

1. 读取任何实例变量
2. 写入任何具有显式初始化的实例变量
3. 在 this 上调用任何方法
4. 将 this 传递给任何其他方法

早期构造上下文的典型用法：参数验证与规范化

```java
class Employee {
    static int nextId;
    
    Employee(double s) {
        if (s < 0) s = 0;           // ✅ 参数验证与规范化
        this("Employee #" + nextId, s);  // 显式构造器调用
    }
    
    Employee(String name, double s) {
        // ...
    }
}
```

## 初始化

### 默认初始化

若字段未显式赋值，JVM 会自动赋予默认值：

```java
public class InitialValues {
    boolean t;          // false
    char c;             // '\u0000'（空字符）
    byte b;             // 0
    short s;            // 0
    int i;              // 0
    long l;             // 0L
    float f;            // 0.0f
    double d;           // 0.0
    Object reference;   // null
}
```

>⚠️ **最佳实践**：始终显式初始化字段。依赖默认值会降低代码可读性。

### 赋值初始化

赋值初始化与方法初始化统称为**「显式初始化」**

```java
public class InitialValues {
    // int i = j;       // ❌ 编译错误：非法前向引用（读取尚未声明的 j）
    int j = 10;
    boolean t = false;
    char c = 'c';
    InitialValues reference = new InitialValues();
}
```

### 方法初始化

```java
public class MethodInit {
    // int j = g(i);    // ❌ 非法前向引用：读取尚未声明的 i
    int i = f();        // ✅ i = 0
    int k = g(i);       // ✅ k = 0（此时 i 已初始化）
    
    int f() { return 0; }
    int g(int n) { return n * 2; }
    
    static int si = h();    // ✅ 静态字段可调用静态方法
    // static int sj = f(); // ❌ 编译错误：静态上下文不能调用实例方法
    
    static int h() { return 0; }
}
```

### 静态初始化块

```java
public class Spoon {
    static int i = 0;           // ① i = 0
    
    static {
        i = 47;                 // ② i = 47
        k = 49;              // ✅ 前向赋值允许
        System.out.println("Static {}");
    }
    
    static int j;           // ③ j = 0（默认值）
    static int k;           // ④ k = 0（覆盖静态块中的赋值）
    
    public static void main(String[] args) {
        System.out.println(i);  // 47
        System.out.println(j);  // 0
        System.out.println(k);  // 49 
    }
}
```

### 实例初始化块

```java
public class Mug {
    int id = 1;                 // ① id = 1
    
    {
        id = 10;                // ② id = 10
        name = "Mug-A";         // ✅ 前向赋值允许
        System.out.println("Instance {}");
    }
    
    String name;                // ③ name = "Mug-A"（实例块已赋值）
    int capacity = 500;         // ④ capacity = 500
    
    Mug() {
        id = 100;               // ⑤ id = 100（构造器最后执行）
        System.out.println("Constructor");
    }
    
    public static void main(String[] args) {
        Mug m = new Mug();
        System.out.println(m.id);       // 100
        System.out.println(m.name);     // Mug-A
        System.out.println(m.capacity); // 500
    }
}
```

### 初始化顺序

静态初始化顺序（类加载时，仅执行一次）

1. 父类静态字段默认初始化（赋零值）
2. 按声明顺序从上到下执行父类静态字段显式初始化、静态初始化块
3. 子类静态字段默认初始化（赋零值）
4. 按声明顺序从上到下执行子类静态字段显式初始化、静态初始化块



实例初始化顺序（每次 `new` 时执行）

1. 为对象分配内存，所有实例字段默认初始化（赋零值）
2. 父类实例初始化
   1. 按声明顺序执行父类实例字段显式初始化与实例初始化块
   2. 执行父类构造器
3. 子类实例初始化
   1. 按声明顺序执行子类实例字段显式初始化与实例初始化块
   2. 执行子类构造器



```java
class Parent {
    static int ps = print("Parent static field");
    static { System.out.println("Parent static block"); }
    int pi = print("Parent instance field");
    { System.out.println("Parent instance block"); }
    Parent() { System.out.println("Parent constructor"); }
    static int print(String s) { System.out.println(s); return 0; }
}

class Child extends Parent {
    static int cs = print("Child static field");
    static { System.out.println("Child static block"); }
    int ci = print("Child instance field");
    { System.out.println("Child instance block"); }
    Child() { System.out.println("Child constructor"); }

    static void main() {
        Child child = new Child();
    }
}

// 输出：
Parent static field
Parent static block
Child static field
Child static block
Parent instance field
Parent instance block
Parent constructor
Child instance field
Child instance block
Child constructor
```



初始化顺序导致的陷阱：

- 陷阱一：实例字段的声明顺序依赖

  ```java
  public class MethodInit {
      int i = f();    // i = 0，而非 10！
      int j = 10;
      
      int f() { return j; }
  }
  ```

  实例字段按声明顺序初始化。调用 `f()` 时，`j` 尚未执行到 `int j = 10`，此时 `j` 处于默认值 `0` 的状态。

- 陷阱二：静态字段的循环初始化（Deadly Embrace）

  ```java
  class Config {
      static final Config DEFAULT = new Config();
      
      String get(String key) { /* ... */ }
      
      public Config() {
          Logger.DEFAULT.log("Config read successfully");
      }
  }
  
  class Logger {
      static final Logger DEFAULT
          = new Logger(Config.DEFAULT.get("logger.default.file"));
      
      void log(String message) { /* ... */ }
  }
  ```

  当首次触发 `Logger` 类初始化（例如访问 `Logger.DEFAULT`）时，实际执行顺序如下：

  1. `Logger` 类开始初始化，执行其 `<clinit>` 方法
  2. `<clinit>` 执行到 `DEFAULT = new Logger(Config.DEFAULT.get(...))`
  3. 求值构造器参数时访问 `Config.DEFAULT`，触发 `Config` 类初始化
  4. `Config` 的 `<clinit>` 执行到 `DEFAULT = new Config()`
  5. `Config` 构造器执行，调用 `Logger.DEFAULT.log(...)`
  6. 此时 `Logger` 类仍在初始化中，其 `DEFAULT` 字段尚未完成显式赋值，值为 `null`（默认值）
  7. 对 `null` 调用 `.log(...)` → NullPointerException

## this

每个实例方法都有一个隐藏参数 this，位于所有显式参数之前，代表着被操作对象的引用。

```java
Banana a = new Banana()
Banana b = new Banana();

// 代码表现形式：
a.peel(1);
b.peel(1);

// 编译后的内部表现形式为：
Banana.peel(a, 1);
Banana.peel(b, 1);
```

如果你想在一个实例方法里获得当前对象的引用，那么就使用 this 关键字：

```java
Banana getBanana() {
	return this;
}
```

>不必在每个实例字段引用和实例方法调用前都加 `this.`。现代 IDE 的语法高亮已经能很好地区分成员与局部变量，过度使用反而会增加视觉噪音。但在消除歧义（如参数与字段同名）、构造器重载以及链式调用等场景中，`this` 是表达意图的重要工具。

## 清理对象

### 垃圾收集器

Java 的**垃圾收集器**（Garbage Collector）会自动回收不再使用的对象内存。但需要注意，GC 只管理 JVM 堆上的对象内存，对于对象持有的其他资源无能为力，例如：

- 本地方法中通过 `malloc` 分配的原生内存
- 文件句柄、Socket 等系统资源

这些资源必须由程序员手动释放。

为此，Java 在 `Object` 类中提供了 `finalize()` 方法，子类可以重写它。GC 在回收对象前可能会调用该方法，但调用时机完全不可预测，甚至可能永远不会被调用。因此，`finalize()` 绝不等于 C++ 的析构函数——后者在对象销毁时必定执行，而前者毫无保证。

最佳实践：始终通过显式方法释放资源，惯用命名如 `close()`、`dispose()`、`clean()` 等，将清理责任明确交给程序员。

>⚠️ 注意：`finalize()` 已在 Java 9 中被标记为废弃（@Deprecated），并在 Java 18 中彻底移除。

## static

static 关键字主要解决以下两类需求：

- **共享数据**：某个字段需要在所有对象间共享，且不依赖于任何对象是否存在
- **独立行为**：某个方法不依赖于对象状态，即使未创建实例也能直接通过类名调用

static 成员是基于类创建的，而实例成员是基于对象创建的。静态方法不持有任何对象引用，因此无法在其中直接访问实例字段、实例方法，也无法使用 `this` 关键字。然而，在实例方法中则可以自由地访问静态成员。



>从设计范式上看，静态方法具有全局函数的语义，这也是一些人认为它不符合纯面向对象思想的原因。至于这是否是"正确的 OOP"，不妨留给理论家去争论。

## final

### 数据 final

数据 final 可以分为以下两类：

- **编译时常量**：对编译时常量来说，编译器可以将常量值「折叠」到计算中（将常量值硬编码到字节码中）。这节省了一些运行时开销。
- **运行时常量**：运行时常量允许延迟初始化。对于基本类型，它的值不变；对于引用类型，一旦它被初始化指向某个对象后，就永远不能指向另一个对象了。但是，对象本身是可以修改的。总而言之，final 确保栈上的值保持不变。

### 方法 final

使用 final 方法的原因有两个：

- OOP 设计：禁止子类通过重写（Override）改变其语义

- 性能优化：

  - **消除动态绑定**：由于 `final` 方法不可被重写，编译器在编译期就能确定调用目标，无需通过虚方法表进行运行时动态分派。这让编译器可以为 final 方法的调用生成更为高效的代码。

  - **方法内联**：编译器直接将对 `final` 方法的调用替换为方法体中实际代码，省去参数压入栈，跳到方法代码处并执行，跳回并清除栈上的参数等调用开销。但这会让代码膨胀。

    >现代编译器已经足够智能，可自行判断是否需要执行方法内联、消除动态绑定的优化，绝大多数情况下不会采纳 `final` 的性能优化提示。因此最好仅将 final 用作设计决策，而不是尝试用它提高性能。长期以来，Java 官方并不鼓励使用 final 来进行性能优化。

此外，类中的任何 private 方法都是隐式的 final。

### 类 final

将整个类定义为 final 时，就阻止了该类的所有继承，此时它的所有方法都是隐式 final 的。

## Main 方法

Java 程序以 `public static void main(String[] args)` 方法作为启动入口。在 Java 25 前，main 方法的签名如下：

```java
class Application {
  public static void main(String[] args) {
    // construct objects here
    . . .
  }
}
```

 Java 25 对 main 方法签名的限制更宽松了，以下是 main 方法的完整规则：

| 访问修饰符                              | 返回值 | 参数                              | `static` |
| --------------------------------------- | ------ | --------------------------------- | -------- |
| `public` / `protected` / 默认（包私有） | `void` | 无参，或 `String[]` / `String...` | 均可     |

当类中存在多个符合条件的 `main` 方法时，按以下优先级选择：

1. `static` 优先于实例方法 — 同时存在静态和实例 `main` 方法时，优先选择静态版本。
2. 带参数优先于无参 — 同时存在 `String[]` 和无参版本时，优先选择带 `String[]` 参数的版本。

如果选中的 `main` 不是静态方法，则该类必须提供一个非私有的无参构造器。启动时，JVM 会先实例化该类，再在该实例上调用 `main` 方法。

## 方法

方法最基础的几个部分包括：**方法名**、**参数列表**、**返回值**，以及**方法体（method body）**：

```
ReturnType methodName(/*参数列表*/)
{
    //方法体
}
```

方法名和参数列表共同构成了方法的**签名（signature）**，方法签名即该方法的唯一标识符。

在 Java 中的方法只能作为类的一部分而存在。例如， `ObjectReference.methodName(arg1, arg2, arg3);`。这种调用方法的行为也被描述为「向一个对象发送一条消息」。

### 方法参数

Java 中所有参数传递均为「按值传递」，即方法形参接收的是实参值的副本：

- 基本类型的实参：方法内修改形参不影响实参；
- 对象类型的实参：方法内可以修改实参所引用对象的内部状态，但无法使实参指向新的对象。

比较遗憾的是，Java 并不支持默认参数，这是出于以下的考量：

1. Java 的设计哲学偏向显式（explicit），在这里体现为「调用者应当清楚自己传递了什么参数，而不是依赖隐藏的默认值」。
2. 默认参数值是编译期常量。如果库作者修改了默认值，所有已编译的调用方仍使用旧值。这与 Java 强调的向后二进制兼容原则冲突。
3. 增加语言复杂性和学习成本。

可以通过方法重载间接支持默认参数：

```java
void connect(String host) {
    connect(host, 8080);
}

void connect(String host, int port) {
    // ...
}
```

### 重载

重载是指在同一个类中，存在多个方法名相同、参数列表不同的方法。参数列表的差异体现在参数个数、参数类型或参数顺序上。

```java
void f(int val, String str);
void f(String str, int val);  // 参数顺序不同，构成重载
```

编译器在重载解析，按以下优先级逐步匹配：

1. 精准匹配（参数类型和个数完全一致）

2. 基本类型自动转型（窄型到宽型）
3. 自动装箱与拆箱
4. 可变长参数

如果存在多个候选方法，且没有任何一个方法比其他所有方法更优先，编译器将报错。

```java
void overload(int i, double j, Integer k);
void overload(byte i, float j, int k);

overload((byte)1, 1.1f, Integer.valueOf(1));
// 调用 overload(int, double, Integer)
// 原因：基本类型拓宽转换（byte→int, float→double）的优先级高于自动装箱（int→Integer）
```

```java
void overload(int i, float j, int k);
void overload(byte i, double j, long k);

overload((byte)1, 1.1f, 1);
// 编译错误：模糊调用
// 原因：两个方法都需要基本类型拓宽转换，不存在优先级差异
```

## Record

>规范：https://openjdk.org/jeps/395

`record` 是 Java 16 引入的不可变数据的透明载体的类，可以视其为具名元组。

编译器会自动为其生成：

- 对于头部中的每个组件，会有两个成员：一个与组件同名且返回类型相同的 `public` 访问器方法，以及一个与组件类型相同的 `private` `final` 字段；
- 一个规范构造函数，其签名与记录头相同，并将每个私有字段赋值为实例化该记录的 `new` 表达式中对应的实参；
- `equals()`、`hashCode()`、`toString()`



与普通类相比，记录类的声明存在诸多限制：

1. 记录类声明不包含 `extends` 子句，它的超类始终是 `java.lang.Record`。即记录类无法显式扩展任何类
2. 记录类隐式为 `final` ，且不能为 `abstract` 
3. 从记录组件派生的字段是 `final` 
4. 记录类不能显式声明实例字段，也不能包含实例初始化块。这些限制确保仅由记录头定义记录值的状态。

除上述限制外，记录类的行为与普通类相同：

1. 记录类可以声明为顶层类或嵌套类，并且可以是泛型类
2. 记录类可以声明 `static` 成员以及实例方法
3. 记录类可以实现接口
4. ...



嵌套和局部`record`隐式是静态的，不持有外部类的引用：

```java
public class NestedLocalRecords {
    int i = 10;
    static int j = 10;
    
    record Nested(String s) {
        void f() {
            // System.out.println(i);  // ❌ 错误：隐式静态，不能访问外部实例成员
            System.out.println(j);     // ✅ 正确：可以访问外部静态成员
        }
    }
    
    void method() {
        record Local(String s) {}     // ✅ 局部 record
    }
}
```



规范构造函数也可以更紧凑地声明，省略其形参列表——**紧凑构造器（compact constructor）**。此时，在构造函数末尾会自动将字段赋值为对应的形参。这种紧凑形式有助于开发者专注于参数的验证和规范化，而无需繁琐地将参数赋值给字段。

```java
record Rational(int num, int denom) {
    Rational {
      	// 这里的 num、denom 是隐式定义的形参
        int gcd = gcd(num, denom);
        num /= gcd;
        denom /= gcd;
    }
}

// 等价于
record Rational(int num, int denom) {
    Rational(int num, int demon) {
        // Normalization
        int gcd = gcd(num, denom);
        num /= gcd;
        denom /= gcd;

        // Initialization
        this.num = num;
        this.denom = denom;
    }
}
```

可以额外地添加自定义构造器：

```java
record Point(int x, int y) {
    Point(int x) {
        this(x, 0);
    }

    Point() {
        this(0, 0);
    }
}
// 此时有三个构造器，一个规范构造器，两个自定义构造器
```
