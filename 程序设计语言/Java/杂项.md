## package-info.java

package-info.java 的作用：
1. 提供包级注释说明
2. 支持定义 default 访问权限的类，便于集中管理友好类
3. 支持添加包注解



## 紧凑源文件

当 Java 编译器遇到包含未封装在类声明中的字段和方法的源文件时，会将其视为一个隐式声明的类，其成员即为这些未封装的字段和方法。此类源文件称为**紧凑源文件**（compact source file）。

隐式声明的类具有以下特性：

- 是未命名包中的 `final` 顶层类
- 继承自 `java.lang.Object` ，且不实现任何接口
- 具有一个自动生成的无参默认构造函数，不允许定义其他构造器、实例初始化块或静态初始化块
- 其成员是紧凑源文件中的字段和方法
- 必须包含一个可执行的 `main` 方法，否则编译报错
- 编译器会为紧凑源文件生成一个类名，但该类名依赖于具体实现，且无法在源代码中引用。
- 默认 import 所有 `java.base` 模块所导出的公共顶层类和接口



```java
void main() {
  . . .
}

int counter = 0;
void work() { 
  counter++;
}

static String name = "AnnoRuo";
static void printName() {
	IO.println(name);
}
```



> 引入该特性的动机（https://openjdk.org/jeps/512）：
>
> 1. 降低 Java 初学者的入门门槛，让教师能够循序渐进地讲授语言概念
> 2. 减少小型程序（如脚本、命令行工具）中的样板代码

## 指定启动类

指定启动类的方式有

- 命令行直接运行：`java -cp "/target/classes" com.example.Main`
- 打包 JAR 时指定：在 `META-INF/MANIFEST.MF` 中添加 `Main-Class: com.example.Main`
- Maven 插件指定：在 `pom.xml` 的 `maven-jar-plugin` 或 `spring-boot-maven-plugin` 中添加 `<mainClass>`

## 编译与运行

javac 命令用于将源代码 `.java` 编译成字节码文件 `.class`：

```java
javac [ options ] [ sourcefiles ] [ @files ]
```

常用选项如下：

- `-sourcepath`：指定用以查找类或接口定义的源代码路径（`.java`）。与用户类路径一样，源路径项用分号 (**;**) 进行分隔，它们可以是目录、JAR 归档文件或 ZIP 归档文件。

  >请将源文件按照其包结构组织在相应的目录树中。例如，如果您的所有源文件都位于 `workspace` 目录下，那么 `com.mysoft.mypack.MyClass` 类的源代码（属于 `workspace` 包）应放在 `workspace\com\mysoft\mypack\MyClass.java` 目录中。否则，当其他模块 import MyClass 时，由于包名与文件路径不匹配，编译器将找不到 MyClass。

  若未指定 `-sourcepath` 选项，则将在用户类路径中查找类文件（`.class`）和源文件（`.java`）

- `-classpath`：设置用户类路径（`.class`），它将覆盖 CLASSPATH 环境变量中的用户类路径。若既未指定 CLASSPATH 又未指定 `-classpath`，则用户类路径由当前目录构成。

- `-d 目录`：设置编译后类文件的输出目录。如果某个类是一个包的组成部分，则 javac 将把该类文件放入对应包名的子目录中，必要时会自动创建目录。若未指定 `-d` 选项，则 javac 将把类文件放到与源文件相同的目录中



javac 的执行过程如下：

1. 解析源代码中导入的全限定类名（`com.google.gson.Gson`）；
2. 将类名中的`.`替换为路径分隔符，得相对路径：`com/google/gson/Gson`；
3. 分空间检索目标文件：
   - 源代码路径作为根路径 ，依照上述相对路径查找后缀为 `.java` 的源代码文件；
   - 用户类路径作为根路径 ，依照上述相对路径查找后缀为 `.class` 的字节码文件；
4. 若同时找到源文件和类文件，javac 会比较两者的修改时间：若类文件早于源文件（即已过时），则重新编译源文件并使用新生成的类文件；否则直接使用现有类文件。
