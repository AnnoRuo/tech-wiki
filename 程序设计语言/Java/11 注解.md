## 概述

Java 注解提供了 Java 源代码无法表达、但完整表述程序所必需的信息（例如，各种中间件的参数配置）。也就是说，可以将一些元数据保存在 Java 源代码中。

然而除了通过注解将元数据保存在 Java 源代码中，还可以通过 XML 配置文件保存这些元数据，并通过 Java 代码读取这些 XML 配置文件获取相应的数据。这两种方法各有优劣：

1. 注解是真正的语言组件，因此是结构化的，并可接受编译时类型检查。将所有信息都保存在真正的代码而不是注释中，会使代码更整洁，且更便于维护。通过直接使用或扩展注解 API 和工具，或者使用外部的字节码处理库（如本章后面所述），可以对源代码以及字节码执行强大的检查和操作。缺点在于配置过于分散
2. XML一个缺陷就是每定义一个 Java 类，程序员都必须经过一个乏味的配置信息的过程，比如配置类名、包名等——这些都是类中本来就有的信息。无论你什么时候使用外部描述符文件，最终都会得到关于一个类的两个独立的信息源，这常常导致代码的信息同步问题，维护成本极大。

## 使用注解

### 注解元素

注解中可以定义称为**「注解元素」（Annotation Elements）**的键/值对，例如：

```java
@RepeatedTest(value=10, failureThreshold=3)
```

如果一个注解未定义任何一个元素，那么称该注解为**标记注解**（空注解）


注解元素的语法规则：

- 所允许的元素类型：所有基本类型、String、Class、Enum、Annotation、前述类型的数组。
	```java
	@BugReport(
		showStopper=true,
		assignedTo="Harry",
		testCase=CacheTest.class,
		status=BugReport.Status.CONFIRMED,
		ref=@Reference(id=11235811),
		reportedBy={"Harry", "Fred"}
	)
	```
- 所有元素值要么是默认值，要么在使用处显式设置
- 禁止将元素值设置为 null
- 由于注解由编译器处理，所有元素值必须是编译时常量
- 设置值会覆盖掉默认值
- 如果元素值是仅包含单个元素的数组，则可以省略花括号
	```java
	@BugReport(reportedBy="Harry") 
	// Same as reportedBy={"Harry"}
	```
### 多个注解与重复注解

一个元素可以拥有多个注解
```java
@Test
@Tag("localized")
void testHello()
```
如果注解定义为 `@Repearable`，那么可以多次重复使用同一注解：

```java
@Tag("localized")
@Tag("showstopper")
void testHello()
```

### 注解声明

注解按照使用场景分为两类：

- **声明注解**（declarations annotation）：来注解程序中的声明结构。例如，类、方法、成员变量、构造器等本身的定义
- **类型使用注解**（type uses annotation）：来注解任何使用类型的语法地方。例如，强制转型、`new` 对象、泛型等

#### 声明注解

声明注解可以在以下场景使用：
- 类（包括 enum）和接口（包括注解接口 @interface）
- 方法
- 构造函数
- 字段（包括 enum 以及 record）
- 局部变量（包括 for 和 try-with-resources 中声明的变量）
- 函数参数和 catch 参数
- 类型参数
- 包和模块

```java
// 类
@Entity 
public class User { . . . }

// 局部变量
@SuppressWarnings("unchecked") List<User> users = . . .;

// 函数参数
public User getUser(@Param("id") String userId)

// record 组件
public record Rectangle(@ToString(includeName=false) Point topLeft, int width, int height) {}

// 类型参数
public class Cache<@NonNull V> { . . . }

// 包
@Generated("com.horstmann.generator")
package com.horstmann.corejava.generated;
import javax.annotation.processing.Generated;
```

注意，局部变量和包上的注解会在编译阶段丢弃，因此它们只能在源码级别处理。

此外，包注解只能在 [package-info.java](./杂项.md#package-info.java) 文件中使用。

#### 类型使用注解

声明注解可以在以下场景使用：

1. 使用泛型类型参数：`List<@NonNull String> `
2. 数组括号前：
   1. `String[] @NonNull [] words`：`String[]` 不为 null
   2. `String @NonNull [][] words`：`String[][]` 不为 null
   3. `@NonNull String[][]`：`String[i][j]` 不为 null
3. 对于超类和已实现的接口：`class Warning extends @Localized Message `
4. 对于构造函数调用：` new @Localized String(. . .) `
5. 对于嵌套类型：`Map.@Localized Entry`
6. 使用强制类型转换和 instanceof 检查：`(@Localized String) text`、`if (text instanceof @Localized String)`
7. 使用异常规范：`public String read() throws @Localized IOException`
8. 使用通配符类型和类型边界：`List<@Localized ? extends Message>`、`List<? extends @Localized Message>`
9. 使用方法引用和构造函数引用：`@Localized Message::getText`

以下类型位置无法添加注解：

- `@NonNull String.class`：class 字面量
- `import java.lang.@NonNull String`：import 语句

通常（但非强制要求）将类型使用注解放在其他修饰符之后，而将声明注解放在其他修饰符之前。例如：

- `private @NonNull String text;`：类型使用注解
- `@Id private String userId`：声明注解

某些情况下，注解可以同时视为为「类型使用注解」以及「声明注解」，例如，`public User getUser(@NonNull String userId)`

### 接收者参数

接收者参数（Receiver Parameter）允许在实例方法或内部类的构造方法中，通过 `this` 关键字明确指定并对当前对象的类型进行注解。它不是真正的形式参数，不影响方法签名。

```java
public class Point {
  public boolean equals(@Nullable Object other) { . . . }
}
```

```java
p.equals(q)
```

此时如果我们想注解调用者 `p`，那么就使用以下语法变体：

```java
public class Point {
  public boolean equals(@NonNull Point this, @Nullable Object other) { . . . }
}
```

注意，构造函数不能接受接收者参数。因为从概念上来讲在构造完成之前，this 引用尚未成为该类型的对象实例；相应地，置于构造函数上的注解可以描述正在构造的对象。

对于内部类的构造方法，会隐式传入外部类对象的引用，我们也可以使用接收者参数显式说明：

```java
static class Sequence {
  private int from;
  class Iterator implements java.util.Iterator<Integer> {
    private int current;
    public Iterator(@NonNull Sequence Sequence.this) {
      this.current = Sequence.this.from;
    }
    . . .
  }
  . . .
}
```

## 定义注解

每个注解都必须通过一个注解接口 `@interface` 来声明：

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RepeatedTest {
  int failureThreshold();
}
```

「注解元素」实际上就是一个方法，但不能包括参数以及 throws 子句。可以通过 default 子句来为注解元素指定默认值：

```java
public @interface RepeatedTest {
  int failureThreshold() default Integer.MAX_VALUE;
  String[] reportedBy() default {};
  Reference ref() default @Reference(id=0);
}
```

所有注解接口都隐式扩展了 java.lang.annotation.Annotation 接口。当在运行时通过反射（如 `getAnnotation()`）获取注解对象时，JVM 并不会直接 new 一个实例，而是通过动态代理（Dynamic Proxy） 生成一个实现了该注解接口的代理对象，以提供对注解属性值的访问。

它的 API 如下：

- `Class<? extends Annotation> annotationType()`：获取注解接口的 Class 对象，而不是 getClass() 所返回内部代理类的 Class 对象

  ```java
  public class Main {
      public static void main(String args[]) {
          try {
              Method method = SampleClass.class.getMethod("demoMethod");
              // 获取方法上的指定注解实例
              Annotation annotation = method.getAnnotation(MyTestAnnotation.class);
  
              if (annotation != null) {
                  System.out.println("getClass() 返回: " + annotation.getClass());
                  // 输出类似: class com.sun.proxy.$Proxy1
  
                  Class<? extends Annotation> type = annotation.annotationType();
                  System.out.println("annotationType() 返回: " + type.getName());
                  // 输出: MyTestAnnotation
  
                  if (type == MyTestAnnotation.class) {
                      System.out.println("成功匹配到 MyTestAnnotation 注解！");
                  }
              }
          } catch (NoSuchMethodException e) {
              System.out.println("no such method");
          }
      }
  }
  
  @Retention(RetentionPolicy.RUNTIME)
  @Target(ElementType.METHOD)
  @interface MyTestAnnotation {
      String value() default "默认值";
  }
  
  class SampleClass {
      @MyTestAnnotation(value = "Hello Java")
      public void demoMethod() {}
  }
  ```

- `boolean equals(Object other)`：如果 other 与注解对象实现了相同的注解接口，并且元素值均相等，则返回 true

- `int hashCode()`

- `String toString()`



通过以下元注解来定义注解的行为：

- @Target（必选）：指定该注解可以应用于哪些元素，其元素值是一个 ElementType 对象数组。如果某个注解未指定 @Target，则它可以用于任何声明中，但不能用在类型使用中。
  
    - METHOD：方法
    
    - PARAMETER：方法或构造函数参数
    
    - ANNOTATION_TYPE：注解接口
    
    - TYPE：类（包括 enum）、接口（包括注解接口）
    
    - LOCAL_VARIABLE：局部变量
    
    - CONSTRUCTOR：构造方法
    
    - FIELD：字段（包括 enum 常量）
    
    - RECORD_COMPONENT：记录组件
    
      ```java
      @Target(ElementType.RECORD_COMPONENT)
      @Retention(RetentionPolicy.RUNTIME)
      @interface RecordComponentAnnotation {
      
      }
      
      record MyRecord(@RecordComponentAnnotation int component) {
      
      }
      ```
    
    - TYPE_PARAMETER：类型参数
    
      ```java
      @Target(ElementType.TYPE_PARAMETER)
      @Retention(RetentionPolicy.RUNTIME)
      public @interface TypeParameterAnnotation {
      
      }
      
      public class TypeParameterClass<@TypeParameterAnnotation T> {
        public <@TypeParameterAnnotation U> T foo(T t) {
          return null;
        }   
      }
      ```
    
    - TYPE_USE：类型使用
    
- @Retention（必选）：保留策略
  
    - RetentionPolicy.SOURCE 源码级注解。注解信息只会保留在 java 源码中，源码在编译后注解信息被丢弃，不会保留在 class 文件
    - RetentionPolicy.CLASS 编译时注解。注解信息会保留在 java 源码以及 class 文件中。当运行 java 程序时，JVM 会丢弃该注解信息，不会保留在 JVM 中
    - RetentionPolicy.RUNTIME 运行时注解，当运行 java 程序时，JVM 也会保留该注解信息，可以通过反射获取该注解信息。
    
- @Documented（可选）

- @Inherited（可选）：让父类上的注解可以被子类自动继承

    ```java
    @Inherited
    @Retention(RetentionPolicy.RUNTIME)
    @Target(ElementType.TYPE)
    public @interface MyAnno {}
    
    @MyAnno
    public class Parent {}
    
    // 隐式继承了 Parent 父类上的 @MyAnno 注解
    public class Child extends Parent {}
    ```

- @Repearable（可选）：用于声明某个注解可以在同一个源代码元素上重复使用多次。出于兼容原因，创建要创建一个可重复的注解，必须完成两个步骤：

    1. 定义实际注解
    2. 定义容器注解：必须包含一个名字为 `value()` 的方法，且该方法的返回值必须是实际注解的数组

    ```java
    @Repeatable(Tag.class)
    @interface Tag {
      String value();
    }
    
    @interface Tags {
      Tag[] value();
    }
    ```

    每当用户提供两个或更多 @Tag 注解时，它们会自动被包装到一个 @Tags 注解中。

## Java API 中的注解

- `@Deprecated`：标记已经弃用的语法元素

- `@Override`：用来告诉编译器，子类中的方法正在重写父类的方法。如果父类中没有这个方法，编译器就会报错

- `@Serial`：用来标记类中与对象序列化相关的字段和方法，让编译器帮你做编译期检查，确保这些序列化声明写得完全正确

  ```java
  public class User implements Serializable {
    @Serial
    private static final long serialVersionUID = 1L; // 检查版本号字段
  
    @Serial
    private void writeObject(java.io.ObjectOutputStream out) throws java.io.IOException {
      out.defaultWriteObject(); // 检查序列化方法签名
    }
  }
  ```

- `@SuppressWarnings`：抑制警告信息

- `@SafeVarargs`：当泛型与可变参数（`varargs`）一起使用时，Java 会因为泛型擦除产生堆污染警告（Heap Pollution）。这个注解向编译器保证：方法内只读取可变参数，不会修改它们，也不会把它们赋给不安全的地方，从而关闭编译器的警告

- `@FunctionalInterface`：显式声明某个接口是一个函数式接口

- `@Generated`：标记由程序或工具自动生成的源代码
