## 硬件概览

![圖0.1.2、電腦的五大單元](assets/computer02.gif)

- 输入单元：负责将外部信息转换为计算机可识别的电信号：

  - 人机交互设备：键盘、鼠标、触控板/触控屏幕
  - 数据采集设备：扫描仪、读卡机、手写板、麦克风、摄像头
  - 传感器类：温度传感器、运动传感器等

- 系统单元：

  - CPU 是计算机的运算和控制核心

    - 算术逻辑单元：负责程序运算与逻辑判断
    - 控制单元：协调各单元间的工作

    >指令集架构（ISA）：CPU 设计的基础规范，主要分为两类：
    >
    >- **RISC（精简指令集）**：指令简单、执行周期固定，代表有 **ARM**（广泛应用于手机、嵌入式设备、路由器等）
    >- **CISC（复杂指令集）**：指令丰富、功能强大，代表有 **Intel x86、AMD x86-64**（主要应用于 PC 和服务器）

  - 主内存（RAM）：用于临时存放正在运行的程序和正在被处理的数据。

  - 主板：主机内各硬件通过主板上的总线（Bus）和插槽连接在一起。主板上的控制芯片组，负责协调 CPU、内存、存储设备、外设之间的数据通信。

  - 存储设备

- 输出单元：将计算机处理结果以人类可感知的形式呈现。例如，显示器、投影仪、音响、打印机、振动马达

### CPU

- CPU 主频：CPU 内核工作的时钟频率。
- CPU 外频：在早期架构中，前端总线 FSB（Front Side Bus）作为 CPU 与北桥芯片的通信总线，负责处理器与北桥芯片间的数据传输。因此所谓的外频指的是 CPU 和外部组件传输数据的基准频率。现代 CPU 已将北桥功能集成至处理器内部，CPU 可直接与内存交互，无需再考虑外频
- CPU 倍频：主频与外频的倍率
- 超频：通过主板配置调高 CPU 倍频或外频，以提升 CPU 主频
- 字长：CPU 单次运算可处理的数据位数
- 超线程：单个物理 CPU 核心可虚拟出两个逻辑核心。其核心原理是在每个 CPU 内设置多组独立寄存器，每组寄存器供不同线程使用。某一线程指令阻塞时，CPU 可切换执行另一线程指令，充分利用硬件资源。

### 内存

RAM 可以分为 

- DRAM（动态随机存取存储器）：用电容存数据，需要持续刷新，成本低、容量大，常做电脑主存。
- SRAM（静态随机存取存储器）：用触发器存数据，不用刷新，速度极快但成本高、容量小，常做CPU高速缓存

DRAM 技术：

| SDRAM/DDR | 型号      | 数据宽度（位） | 内部时钟频率（MHz） | 频率速度 | 带宽（频率 x 宽度） |
| --------- | --------- | -------------- | ------------------- | -------- | ------------------- |
| SDRAM     | PC100     | 64             | 100                 | 100      | 800MBytes/sec       |
| SDRAM     | PC133     | 64             | 133                 | 133      | 1064MBytes/sec      |
| DDR       | DDR-266   | 64             | 133                 | 266      | 2.1GBytes/秒        |

| DDR       | DDR3-1600 | 64             | 200                 | 1600     | 12.8GBytes/秒       |

DDR 是指双倍数据传送速度（Double Data Rate），它可以在一个工作周期内进行两次数据传输，与 CPU 倍频概念相似。其中，DDR2 的频率倍数为 4 倍，而 DDR3 则为 8 倍。

此外，某些主板还支持 DRAM 双通道功能，即两根主内存整合在一起。若单根内存的数据宽度可达 64 位，两根内存的即可达到 128 位，从而提升带宽。当启动双通道功能时，必须将两根容量相同的主内存插入主板中相同颜色的插槽里。

### 主板

![圖 0.2.1、Intel晶片架構](assets/chipset_z87.jpg)

由于外设访问速度的差异，早期的主板芯片组通常分为两个桥接器来控制各组件间的通信：

- 北桥（传统架构）：负责高速设备（CPU、内存、显卡）
- 南桥：负责低速 I/O 设备（USB、SATA、音频等）

现代 CPU 已将北桥功能集成到芯片内部。

>注意，由受到于 CPU 引脚以及内存插槽规格、工作电压的限制，同主板支持的 CPU 和内存型号存在差异

#### 设备 I/O 地址

IO 地址（输入/输出地址，Input/Output Address）是计算机CPU用来与硬盘、键盘、网卡等外部设备进行通信的专用地址。通过这些地址，CPU可以向设备发送指令或读取数据。有两种编址方式：

- 统一编址 （存储器映射方式, MMIO）：外设的I/O寄存器与主存单元共用同一个地址空间。不需要专门的I/O指令，直接使用访存指令（如 `MOV`、`ADD` 等）对设备读写。
- 独立编址（I/O映射方式, I/O Port）：主存地址空间和I/O地址空间是完全独立的两套系统。必须使用专用的I/O指令（如x86的 `IN` 和 `OUT`）来读写外设。

IRQ（Interrupt Request，中断请求）是硬件设备通知中央处理器（CPU）处理紧急任务的一种信号机制。当外设（如键盘、网卡、硬盘）有数据需要处理时，会向 CPU 发送 IRQ 中断。CPU 暂停当前任务并保存状态，运行中断服务程序。处理完成后，回到原本的任务继续执行。

#### DMA

在没有 DMA 技术之前，所有内存与外设之间的数据传输都必须由 CPU 亲自搬运，即逐个字节地把数据从外设读入寄存器，然后再写入内存，导致 CPU 被严重占用。

![img](assets/v2-2ad2ec819e69e106d44704fab3c141b1_1440w.jpg)

DMA（直接内存访问）：在 I/O 设备与内存进行数据传输时，CPU 只需初始化 DMA 控制器（设定源地址、目标地址和传输长度），后续的实际数据搬运工作由 DMA 控制器独立完成。传输期间 CPU 可执行其他任务，传输完成后 DMA 向 CPU 发送中断信号通知其进行后续处理。

![img](assets/v2-282ecfe51a18f00918f02f02bdf20950_1440w.jpg)

#### CMOS 与 BIOS

- 固件（firmware）：烧录在硬件里的程序，负责控制硬件的最底层基本功能
- BIOS：全称基本输入输出系统，控制电脑开机自检、硬件初始化以及加载引导程序等等，也是一种固件。电脑按下开机键后，CPU 通电并重置，程序计数器被硬件强制设置为一个固定的初始地址（x86 架构下通常为 0xFFFFFFF0），该地址映射到主板上的 ROM/Flash 芯片，CPU 从此处开始执行 BIOS 固件代码。
- CMOS：存储 BIOS 程序的配置参数（例如，CPU 电压与频率、各项设备的 I/O 地址与 IRQ 等）的 RAM 芯片。依靠主板纽扣电池维持数据，断电后，CMOS 参数全部恢复出厂默认值。
- ROM：只读存储器，现在多指可擦写的闪存芯片，用来长期保存固件代码和数据。

### 硬盘



![圖0.2.4、硬碟物理構造(圖片取自維基百科)](assets/hard_disk01.jpg)

硬盘由多个磁盘盘片、机械臂、多个磁头读写装置以及主轴马达所组成的。在实际运作时，主轴马达带动磁盘盘片旋转，随后机械臂伸展，使读取头在盘片上执行读写动作。

![磁盘结构.png](assets/215c28364c67488ca4e0334ab0ca13c6tplv-k3u1fbpfcp-zoom-in-crop-mark1512000.webp)

- 扇区（sector）：磁盘最小的物理存储单元
- 磁道（track）：由位于同一同心圆上的若干扇区所构成的
- 柱面（cylinder）：由所有盘片上半径相同的磁道共同组成的

给定任意一个扇区，如果想要读取该扇区的数据，需要三个步骤：

- 寻道：通过移动磁头，找到数据所在的磁道（柱面），这个过程叫寻道延迟，大概会消耗3～15ms
- 旋转：通过旋转定位到磁头上具体的扇区，这个过程叫旋转延迟，大概会消耗2～4ms
- 读写数据：这个过程速度很快，可以忽略不计；

磁盘上的任意扇区都可以通过（磁头号，磁道号，扇区号）的三元组唯一标识。磁头号、磁道号从 0 开始编号，扇区号从 1 开始编号。出于读写效率考量，数据的写入顺序以柱面为单位：自上而下（注意，单块盘片的正反两面均可存储数据），由外向内。



## 操作系统

操作系统的作用：

1. 以高效合理的方式组织与管理计算机各类资源
   1. 硬件资源：`CPU`、内存、设备（`I/O`设备、磁盘、时钟、网络卡等）
   2. 软件资源：磁盘上的文件、各类管理信息等
2. 为用户提供了一组功能强大、方便易用的命令或系统调用。例如，进程的创建与执行、文件和目录的操作等等。在应用程序和硬件之间构建抽象的扩展机器（虚拟机），对硬件进行封装抽象，提升软件可移植性。



操作系统划两种运行级别。

- **用户态**：权限较低，供普通应用程序运行，不能直接操作硬件
- **内核态**：拥有最高权限，可以控制所有硬件与系统资源。用户态的应用程序可以通过三种方式来访问内核态的资源：系统调用、库函数以及 Shell 脚本。

## 磁盘分割

 Linux 系统中，**一切皆文件**（Everything is a file）是核心设计哲学之一，硬件设备也不例外。系统通过 `/dev` 目录下的特殊文件来抽象和访问硬件。下表列出了常见设备类型及其对应的设备文件名：

| 设备类型                   | 设备文件名                     | 备注                                                     |
| :------------------------- | :----------------------------- | :------------------------------------------------------- |
| **SCSI/SATA/USB 硬盘**     | `/dev/sd[a-p]`                 | 现代系统最常见的块设备命名方式                           |
| **USB 闪存盘**             | `/dev/sd[a-p]`                 | 与 SATA 硬盘共用同一命名规则，依插入顺序分配             |
| **VirtIO 虚拟磁盘**        | `/dev/vd[a-p]`                 | 用于 KVM/QEMU 等虚拟机环境                               |
| **NVMe 固态硬盘**          | `/dev/nvme[0-9]n[1-9]`         | 如 `/dev/nvme0n1`，现代高性能 SSD 的标准命名             |
| **CD/DVD 光驱**            | `/dev/sr[0-1]` 或 `/dev/cdrom` | `sr` 为 SCSI 命名，`cdrom` 通常是指向实际设备的软链接    |
| **鼠标**                   | `/dev/input/mouse[0-15]`       | 通用输入层设备文件；`/dev/mouse` 为当前鼠标软链接        |
| **打印机**                 | `/dev/usb/lp[0-15]`            | USB 接口打印机；传统并口打印机 `/dev/lp[0-2]` 已极为罕见 |
| **终端/控制台**            | `/dev/tty[0-63]`               | 虚拟控制台；`/dev/ttyS[0-3]` 为串口终端                  |
| **随机数设备**             | `/dev/random`、`/dev/urandom`  | 提供内核熵池生成的随机数据                               |
| **零设备/空设备**          | `/dev/zero`、`/dev/null`       | 常用于数据丢弃或生成空数据流                             |

### MSDOS（MBR）分区表

早期 Linux 为了能识别 Windows 硬盘，沿用了 Windows 的 MBR 分区方案；磁盘最开头第 1 个扇区（512 字节）包括以下两项数据：

- **主引导记录区（Master Boot Record, MBR）**：引导代码，占 446 字节。BIOS 开机后，读取磁盘第一个扇区，把这 446 字节代码加载到内存执行，来引导操作系统的加载
- **分区表（partition table）**：记录整块硬盘的分区状态，占 64 字节。每一条分区项占 16 字节，最多只能 4 条**主分区记录**。每条 16 字节记录：分区类型、起始 CHS（柱面 / 磁头 / 扇区）、结束 CHS、LBA 起始地址、分区大小
- 扇区最后 2 字节，固定是 `0x55 0xAA`。BIOS 读到这两个字节，才认定这是一个合法可引导的 MBR 磁盘；

若将硬盘视为长条形，并将柱面以直条图表示，那么这 64 字节的记录区段便类似于下图所示（分区是以柱面为单位的连续磁盘空间 ）：

![圖2.2.2、磁碟分割表的作用示意圖](assets/partition-1.png)

假设上面的硬盘设备文件名为/dev/sda，那么这四个分区在 Linux 系统中的设备文件名就是在 /dev/sda 后按序接一个数字，例如：

- P1:/dev/sda1
- P2:/dev/sda2
- P3:/dev/sda3
- P4:/dev/sda4

当硬盘分区超过 4 个时，需引入**扩展分区**。它是一种特殊的主分区，仅作为逻辑分区的容器，不可格式化或直接挂载。扩展分区内部可划分多个**逻辑分区**，数据实际存储于逻辑分区中。每个逻辑分区头部包含一个**EBR（扩展引导记录）**扇区，记录本分区的信息及下一个 EBR 的位置。由于操作系统限制，最多只有一个扩展分区。

![圖2.2.3、磁碟分割表的作用示意圖](assets/partition-2.png)

同样地，上图中的分区在 Linux 系统中的设备文件名分别如下：

- P1:/dev/sda1
- P2:/dev/sda2
- L1:/dev/sda5
- L2:/dev/sda6
- L3:/dev/sda7
- L4：/dev/sda8
- L5:/dev/sda9

>注意：/dev/sda1 ~ /dev/sda4 是保留给主分区使用的，扩展分区从 /dev/sda5 开始



### GPT 分区表

MBR 分区表有以下痛点：

- **寻址空间有限**：采用 32 位 LBA 寻址，最多支持 $2^{32}$  个扇区。按每扇区 512 字节计算，最大可寻址容量为 **2 TiB**。
- **单点故障风险**：MBR 仅占用一个 512 字节扇区，一旦损坏，分区信息往往难以恢复。
- **引导代码空间不足**：留给引导程序的区域仅 446 字节，无法容纳更多代码



为了解决这些问题，GPT 作为新一代分区方案被设计出来。GPT 使用 64 位 LBA 寻址方式。

>早期的机械硬盘，物理扇区和逻辑扇区都是 512 字节。从 2010 年左右开始，机械硬盘厂商为了提升存储密度和纠错效率，将物理扇区改为 4096 字节（4 KiB），但对外暴露以下逻辑接口：
>
>| 类型                     | 物理扇区 | 逻辑扇区 | 说明                                                      |
>| :----------------------- | :------- | :------- | :-------------------------------------------------------- |
>| **512n**（原生 512B）    | 512B     | 512B     |                                                           |
>| **512e**（512 字节模拟） | 4K       | 512 B    | 一个物理扇区对外表现为 8 个 512 字节的逻辑块。            |
>| **4Kn**（原生 4K）       | 4K       | 4K       | 物理和逻辑扇区都是 4K，效率最高，但需要操作系统/BIOS 支持 |
>
>512e 的以下两个问题会影响到读写效率
>
>- 未对齐：逻辑扇区和物理扇区未对齐，导致一次逻辑扇区的写入会映射成两次物理扇区的写入。现代操作系统在格式化时会自动对齐。
>
>  ![img](assets/118164-20180124110409490-1129387153.jpg)
>
>- 写放大（又称 Read-Modify-Write）：当写入数据小于 4k时，要先将一个扇区数据读出，修改后再写入。
>
>  ![image.png](assets/4v5dzky2miwio_b8cc3b6d593543d7964cd0f75937603c.webp)

- LBA0：但出于兼容性考虑，硬盘的第一个扇区仍然用作 MBR
- LBA1：本节记录了分区表本身的位置和大小，并包含分区表校验码（CRC32）。如果操作系统发现校验码错误，则从备份区恢复.
- LBA2-33：从 LBA2 区块开始， 每个 LBA 都可以记录 4 条分区记录，因此在默认情况下，总共可以有 4*32 = 128 条分区记录。GPT 中的每个分区都可以认为是 MBR 主分区，不再有主分区、扩展分区和逻辑分区的概念
- LBA-33 ~ LBA-1：作为 LBA1 ~ LBA 33 的备份

### 目录树

![圖2.2.9、目錄樹相關性示意圖](assets/dirtree.gif)



| 目录    | 全称/含义                              | 说明                                                         |
| ------- | -------------------------------------- | ------------------------------------------------------------ |
| `/`     | Root                                   | 根目录，整个文件系统的起点                                   |
| `/bin`  | Binaries                               | 存放基本用户命令（如 `ls`、`cp`、`cat`、`bash`），单用户模式（救援模式）下也可用 |
| `/sbin` | System Binaries                        | 存放系统用户命令（如 `fdisk`、`fsck`、`reboot`），通常需要 root 权限 |
| `/boot` | Boot                                   | 存放引导加载器所需的文件（内核 `vmlinuz`、`initramfs`、GRUB 配置等） |
| `/lib`  | Libraries                              | 存放 `/bin` 和 `/sbin` 中程序所需的共享库（如 `libc.so`）    |
| `/etc`  | Editable Text Configuration / Etcetera | 存放系统级配置文件（如 `fstab`、`passwd`、`ssh/`），不含用户个人配置 |
| `/dev`  | Devices                                | 存放设备文件（如 `/dev/sda` 硬盘、`/dev/null` 黑洞、`/dev/tty` 终端），由内核动态生成 |
| `/sys`  | System                                 | 虚拟文件系统，暴露内核和硬件信息（如总线、设备、驱动），可读写以调整内核参数 |
| `/home` | Home                                   | 普通用户的主目录，如 `/home/alice`、`/home/bob`              |
| `/root` | Root                                   | root 用户的主目录                                            |
| `/srv`  | Service                                | 存放本机对外提供服务的数据（如 Web 站点的 `/srv/www`、FTP 的 `/srv/ftp`） |
| `/opt`  | Optional                               | 存放可选的第三方大型软件（如商业软件、独立应用包），通常每个软件独占一个子目录 |
| `/tmp`  | Temporary                              | 存放临时文件，任何用户可读写，系统重启后通常会被清空（或由 `tmpfs` 管理） |
| `/run`  | Run                                    | 存放系统启动后的运行时变量（如 PID 文件、套接字、锁文件），是 `tmpfs` 挂载点，重启即清空 |
| `/var`  | Variable                               | 存放经常变化的数据，如日志、缓存、邮件队列、数据库文件。     |
| `/usr`  |                                        | 存放用户级的只读程序和数据                                   |
| `/proc` |                                        | 虚拟文件系统，映射内核运行时的进程和系统信息。每个进程有一个以 PID 命名的子目录（如 `/proc/1234/`），还有 `/proc/cpuinfo`、`/proc/meminfo` 等系统状态文件 |
