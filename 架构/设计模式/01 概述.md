软件开发是属于工程领域的，而该领域演进的底层逻辑就是提高生产效率。这种观点在软件开发上体现为，**以最小的代价完成代码的修改**。我们可以通过「代码质量」来量化这种代价，它的主要评价指标有：

- **可维护性（maintainability）**：在不破坏原有代码设计、不引入新的 bug 的情况下，能够快速地修改或者添加代码。

- **可扩展性（extensibility）**：表示代码应对未来需求变化的能力，即在不修改或少量修改原有代码的情况下，通过扩展的方式添加新的功能代码。

  > 可维护性蕴含着可扩展性

- **可复用性（reusability）**：尽量减少重复代码的编写，复用已有的代码，前提是所复用的代码要足够的抽象通用。

- **灵活性（flexibility）**：灵活这个词的含义非常宽泛，很多场景下都可以使用，例如代码易扩展、易复用或者易用（例如，这组接口可以应对各种使用场景，满足各种不同的需求）

- **简洁性（simplicity）**：它与 KISS 原则（Keep It Simple、Stupid）密切相关。很多编程经验不足的程序员会觉得，简单的代码没有技术含量，喜欢在项目中引入一些复杂的设计模式，认为这样才能体现自己的技术水平。但是**思从深而行从简**，真正的 Master 总会云淡风轻地用最简单的方法解决最复杂的问题。

- **可读性（readability）**：“Any fool can write code that a computer can understand. Good programmers write code that humans can understand.”。我们可以通过编码规范、命名是否达意、注释是否详尽、函数是否长短合适、模块划分是否清晰等方面，来评价一段代码的可读性。
