# 继承

## 概述

在 Java 中，所有类都直接或间接地继承自 `Object`。当你没有使用 `extends` 显式指定父类时，编译器会自动让你的类隐式继承 `Object`。显式继承则通过 `extends` 关键字实现：

```
class Sub extends Super {}
```

## 复用——继承与组合

在新类中创建现有类的对象。这称为**组合（composition）**。你复用的是代码的功能，而不是其形式。继承直接复制了现有类的形式，然后向新类中添加代码，而没有修改现有类。这种技术叫作**继承（inheritance）**。它的大部分工作是由编译器完成的。

继承一般表示 `is-a`的关系，而组合表示`has-a`的关系。而且组合允许其状态发生改变，继承允许行为发生改变（多态）。

## 隐藏 & 封装

| 任何人      | 同一个包 | 子类 | 本类 |      |
| ----------- | -------- | ---- | ---- | ---- |
| `public`    | ✔️        | ✔️    | ✔️    | ✔️    |
| `protected` |          | ✔️    | ✔️    | ✔️    |
| `default`   |          |      | ✔️    | ✔️    |
| `private`   |          |      |      | ✔️    |

- 在继承时不允许降低父类方法的可访问性
- private 是隐式 final 的
- 如果无参构造器是唯一定义的构造器，并且它是 private 的，那么这就阻止了该类的继承！

再次强调：`private` 是编译期的语法约束，而非二进制层面的保护。它无法防止反编译。它的真正价值在于信息隐藏——将类的内部实现与公开接口明确分开。对类作者而言，这意味着可以自由修改内部实现而不必担心破坏外部依赖；对类使用者而言，这是一种减负：只需关注公开的接口，无需理解内部细节，从而更容易正确使用这个类。

## 多态

封装将实现与接口解耦。而多态（也称动态绑定、后期绑定或运行时绑定）实现类型之间的解耦，即让一段代码同等地适用于所有这些不同的类型，同时在行为上又有所不同。这改善了代码的组织结构和可读性，并且还能创建可扩展的程序。多态是「将变化的事物与不变的事物分离」的一项重要技术。因此大部分面向对象的设计模式依赖于多态机制！

## 转型

向上转型总是安全的，因为你是从更具体的类型转为更通用的类型。在向上转型期间，子类接口缩小至基类的接口。

因为向上转型会丢失特定类型的信息，所以我们自然就可以通过向下转型（downcast）来重新获取类型信息。而向下转型不总是安全的，因为它可能转型为错误的类型，而向该对象发送它无法接受的信息，从而在运行时抛出`ClassCastException`。如果 A 要向下转型为 B，那么 B 的继承链中必须要有 A

## 绑定（覆写）

将一个方法调用与方法体关联起来的动作称为「**绑定**」。在程序运行之前完成的绑定（如果有编译器和链接器，由它们负责实现）称为「**前期绑定**」；在运行时根据对象的实际类型决定调用哪个方法体，则称为「**后期绑定**」。Java 中所有的方法默认都采用后期绑定，唯一的例外是 `static` 方法和 `final` 方法——它们在编译期即可确定，属于前期绑定。

```java
class A {
    void f() {
        g(); // 此处调用的不一定是 A 中的 g()，还可能是子类 B 中重写后的 g()
    }
    void g() {}
}

class B extends A {
    @Override void g() {}
}
```

因此，在 Java 中务必留意：本类内部调用的方法，在运行时可能被动态绑定到子类重写的方法上——即使调用发生在基类的代码中也不例外。

需要特别说明的是，只有普通实例方法具有多态性。`final` 方法、`static` 方法以及字段都不参与动态绑定，而是在编译时静态解析。这带来一个副作用——**名字隐藏（name hiding）**：当子类声明了与基类同名的字段或静态方法时，基类的成员并不会被覆盖，而是被隐藏（不可见）。此时若想访问基类的成员，必须通过 `super` 关键字显式指定：

```java
class Super {
    public int field = 0;
}

class Sub extends Super {
    public int field = 1;

    public int getField() {       // 返回 1，即 Sub 的 field
        return field;
    }

    public int getSuperField() {  // 返回 0，即 Super 的 field
        return super.field;
    }
}
```



在基类构造器执行期间，子类对象尚未构造完成——此时只有基类部分完成了初始化。但由于动态绑定，基类构造器中调用的方法仍可能被绑定到子类的重写版本，而此刻子类的字段还没有初始化（基本类型会被默认置零），由此产生的错误往往十分隐蔽。下面的例子展示了这一问题：

```java
class Glyph {
  void draw() { System.out.println("Glyph.draw()"); }
  
  Glyph() {
    System.out.println("Glyph() before draw()");
    draw();
    System.out.println("Glyph() after draw()");
  }
}

class RoundGlyph extends Glyph {
  private int radius = 1;
  
  RoundGlyph(int r) {
    radius = r;
    System.out.println(
      "RoundGlyph.RoundGlyph(), radius = " + radius);
  }
  
  @Override 
  void draw() {
    System.out.println(
      "RoundGlyph.draw(), radius = " + radius);
  }
}

public class PolyConstructors {
  public static void main(String[] args) {
    new RoundGlyph(5);
  }
}
/* Output:
Glyph() before draw()
RoundGlyph.draw(), radius = 0     // 期望输出 radius = 1
Glyph() after draw()
RoundGlyph.RoundGlyph(), radius = 5
*/
```

因此，编写构造器时有一条很好的准则：「用尽可能少的操作使对象进入正常状态；如果可以避免，不要在构造器中调用本类的其他方法」 唯一可以安全调用的，是基类中的 `final`、`private` 或 `static` 方法——这些方法都无法被子类重写，因而不会产生上述令人意外的行为。

## 协变返回类型

**协变返回类型（covariant return type）**：子类重写方法时，其返回类型可以是基类方法返回类型的子类型。

## 密封类

密封类限制了能派生出哪些类。这让我们可以对固定的一组类型进行建模。（枚举限制了该类的对象，对固定一组对象进行建模）

## 抽象类

通过`abstract`关键字创建抽象类：

```java
abstract class AbstractClass {}
```



抽象类包含任意多个（包括0个）抽象方法，且抽象方法只能声明在抽象类中。抽象方法（abstract method）是一个不完整方法，它只有声明没有方法体，这类似于C++中的纯虚函数（pure virtual function）。

由于抽象类是不完整的，编译器不允许直接实例化它；但抽象类仍然可以作为引用类型，接受子类对象的向上转型：

```java
abstract class A {}
class B extends A {}

A a = new A();    // 编译错误：抽象类不能实例化
A a = new B();    // 正确：向上转型
```

子类继承抽象类后，**必须实现基类中所有的抽象方法**，否则它自己也必须声明为抽象类。抽象类对成员的访问权限几乎没有限制，但有一个例外：禁止将抽象方法声明为 `private`——`private` 方法对子类不可见，子类根本无法提供实现

虽然抽象方法只提供了声明，但是它还实现了对基类方法的覆写：

```java
class T {
  void f() {}
  final void g() {}
}
abstract class R extends T {
  @Override 
  abstract void f();

  // void g(); 不允许覆写
}
```



由于动态绑定，抽象方法可以在类的普通方法中被调用：

```java
class A {
  abstract void f();
  void g () { 
    f(); 
  }
}
```

## 接口

**接口提供了一种更加结构化的方式来分离接口与实现。**接口实现了类型的完全解耦！而多态只实现了在继承层次上的类型解耦。

## Object 与 Objects

- `static <T> void requireNonNull(T obj)`、`static <T> void requireNonNull(T obj, String message)`、`static <T> void requireNonNull(T obj, Supplier<String> messageSupplier)`：

  如果 obj 为 null ，这些方法将抛出指定消息（如果有的话）的 NullPointerException

- `static <T> T requireNonNullElse(T obj, T defaultObj)`、`static <T> T requireNonNullElseGet(T obj, Supplier<T> defaultSupplier)`：

  如果 obj 不是 null ，则返回 obj；如果 obj 为 null ，则返回默认对象
