## 紧凑源文件

当 Java 编译器遇到包含未封装在类声明中的字段和方法的源文件时，会将其视为一个隐式声明的类，其成员即为这些未封装的字段和方法。此类源文件称为**紧凑源文件**（compact source file）。

隐式声明的类具有以下特性：

- 是未命名包中的 `final` 顶层类
- 继承自 `java.lang.Object` ，且不实现任何接口
- 具有一个自动生成的无参默认构造函数，不允许定义其他构造器、实例初始化块或静态初始化块
- 其成员是紧凑源文件中的字段和方法
- 必须包含一个可执行的 `main` 方法，否则编译报错
- 编译器会为紧凑源文件生成一个类名，但该类名依赖于具体实现，且无法在源代码中引用。
- 默认 import 所有 `java.base` 模块所导出的公共顶层类和接口

```java
void main() {
  . . .
}

int counter = 0;
void work() { 
  counter++;
}

static String name = "AnnoRuo";
static void printName() {
	IO.println(name);
}
```



> 引入该特性的动机（https://openjdk.org/jeps/512）：
>
> 1. 降低 Java 初学者的入门门槛，让教师能够循序渐进地讲授语言概念
> 2. 减少小型程序（如脚本、命令行工具）中的样板代码

## 指定启动类

指定启动类的方式有

- 命令行直接运行：`java -cp "/target/classes" com.example.Main`
- 打包 JAR 时指定：在 `META-INF/MANIFEST.MF` 中添加 `Main-Class: com.example.Main`
- Maven 插件指定：在 `pom.xml` 的 `maven-jar-plugin` 或 `spring-boot-maven-plugin` 中添加 `<mainClass>`

## Javac 编译命令

javac 命令用于将源代码 `.java` 编译成字节码文件 `.class`：

```java
javac [ options ] [ sourcefiles ] [ @files ]
```

```bash
# 编译 cn/atsukoruo/Main.java，将生成的 .class 文件输出到 bin 目录
# -d bin：指定编译输出目录
# -sourcepath .：当代码 import 其他类时，从当前目录递归搜索对应的 .java 源文件
javac -sourcepath . -d bin cn/atsukoruo/Main.java
```

常用选项如下：

- `-sourcepath`：指定用以查找类或接口定义的源代码路径（`.java`）。与用户类路径一样，源路径项用分号 (**;**) 进行分隔，它们可以是目录、JAR 归档文件或 ZIP 归档文件。

  >请将源文件按照其包结构组织在相应的目录树中。例如，如果您的所有源文件都位于 `workspace` 目录下，那么 `com.mysoft.mypack.MyClass` 类的源代码（属于 `workspace` 包）应放在 `workspace\com\mysoft\mypack\MyClass.java` 目录中。否则，当其他模块 import MyClass 时，由于包名与文件路径不匹配，编译器将找不到 MyClass。

  若未指定 `-sourcepath` 选项，则将在用户类路径中查找类文件（`.class`）和源文件（`.java`）

- `-classpath`：设置用户类路径（`.class`），它将覆盖 CLASSPATH 环境变量中的用户类路径。若既未指定 CLASSPATH 又未指定 `-classpath`，则用户类路径由当前目录构成。

- `-d 目录`：设置编译后类文件的输出目录。如果某个类是一个包的组成部分，则 javac 将把该类文件放入对应包名的子目录中，必要时会自动创建目录。若未指定 `-d` 选项，则 javac 将把类文件放到与源文件相同的目录中

- `--release`：跨版本安全编译选项（JDK 9+）

  传统组合 `-source`（限制源码语法版本）与 `-target`（限制字节码目标版本）的缺陷：

  ```bash
  # 用 JDK 11 编译，声称兼容 Java 8
  javac -source 8 -target 8 MyClass.java
  ```

  编译器默认仍使用当前 JDK 的最新 API。如果代码调用了 Java 9+ 才有的方法（如 `String.isBlank()`），编译会通过，但放到 Java 8 运行时会抛出 `NoSuchMethodError`。而 `--release` 会在编译期就拦截这种 API 越界：

  ```bash
  javac --release 8 MyClass.java
  # 编译报错：找不到符号 isBlank()
  ```



javac 的执行过程如下：

1. 解析源代码中导入的全限定类名（`com.google.gson.Gson`）；
2. 将类名中的`.`替换为路径分隔符，得相对路径：`com/google/gson/Gson`；
3. 分空间检索目标文件：
   - 源代码路径作为根路径 ，依照上述相对路径查找后缀为 `.java` 的源代码文件；
   - 用户类路径作为根路径 ，依照上述相对路径查找后缀为 `.class` 的字节码文件；
4. 若同时找到源文件和类文件，javac 会比较两者的修改时间：若类文件早于源文件（即已过时），则重新编译源文件并使用新生成的类文件；否则直接使用现有类文件。

## Java 运行命令

`java` 是 JDK 的 Java 应用程序启动器，用于运行编译后的 `.class` 字节码或 `.jar` 包。

```bash
# 运行类文件（需指定完整类名，含包名）
java [options] classname [args...]

# 运行 JAR 包（需 JAR 内 manifest 指定 Main-Class）
java [options] -jar jarfile [args...]

# 运行模块（JDK 9+）
java [options] --module module[/classname] [args...]
```

常用参数：

- 类路径与模块
  - `-cp`：指定用户类路径（覆盖 `CLASSPATH` 环境变量）
  - `-p`：指定模块路径（JDK 9+）
  - `-add-modules`：添加额外模块（JDK 9+）
  - `-Dname=value`： 设置系统属性
- 内存与性能
  - `-Xms<size>`：初始堆内存（如 `-Xms512m`）
  - `-Xss<size>`： 线程栈大小
  - ...
- 垃圾收集器（GC）
  - `-XX:+UseG1GC`：G1 垃圾收集器（JDK 9+ 默认）
  - `-XX:+UseZGC`：ZGC 低延迟收集器（JDK 11+）
  - ...
- 调试与诊断
  - `-verbose:gc`：显示 GC 日志
  - `-agentlib:jdwp=...`：启用 JDWP 远程调试
  - `-Xprof`：性能分析
- 其他：
  - `-splash:image.png`：显示启动画面
  - `-ea`：启用断言
  - `-Dfile.encoding=UTF-8`：设置默认文件编码

## 文档注释 Javadoc

Javadoc 是 Java 官方提供的文档生成工具。它能解析源代码中以 `/**` 开头的特殊注释，自动生成结构化的 HTML 格式 API 帮助文档

```java
/**
 * 这是一个类或接口的说明摘要。
 * 详细描述信息写在这里。
 * 
 * @author 作者名
 * @version 1.0
 */
public class Utils {

    /**
     * 计算两个数字的和。
     *
     * @param a 第一个加数
     * @param b 第二个加数
     * @return 返回两数相加的结果
     * @throws IllegalArgumentException 如果参数为负数
     */
    public int add(int a, int b) {
        return a + b;
    }
}

```

Javadoc 支持三种标记形式：

- **块标签**：以 `@tagname` 形式出现，须独占一行
- **内联标签**：以 `{@tagname 内容}` 形式嵌入行内文本
- **HTML 标签**：直接使用标准 HTML 进行富文本格式化



常用的块标签：

- `@param variable description`：描述方法入参

- `@return description`：描述方法返回值含义

- `@throws class description`：描述方法抛出的异常

- `@see reference`：在「另请参阅」区域生成超链接。`reference` 支持以下多种形式：

  1. 类 / 成员引用：`package.class#member label`
  2. HTML 超链接：`<a href=". . .">label</a>`
  3. 文本引用：`"text"`

  ```java
  // 引用类普通成员
  @see com.horstmann.corejava.Employee#raiseSalary(double)
  
  // 构造函数固定使用 <init>，而非类名
  @see com.horstmann.corejava.Employee#<init>()
  
  // 外部网页链接
  @see <a href="horstmann.com/corejava.html">The Core Java home page</a>
  
  // 文本书籍引用
  @see "Core Java Volume 2"
  ```

- `@deprecated` ：标记已废弃 API，必须配合 `@Deprecated` 注解同时使用。标签后填写说明文本，写明弃用时间、弃用原因，并给出替代方案。



常用的内联标签：

- `@code`：输出等宽代码片段，无需手动处理 HTML 转义，可自动转义 `<`、`&` 等特殊字符。

  多行代码两种写法：

  ```java
  /**
   * 方式1：pre包裹{@code}（通用兼容版本）
   *
   * <pre>{@code
   * // 多行代码
   * }</pre>
   */
  
  /**
   * 方式2：{@snippet}，Java 18+ 支持
   *
   * {@snippet :
   * // 多行代码
   * }
   */
  ```

- `{@link reference}`：生成行内代码样式超链接，引用语法与 @see 标签相同。

  >Java 20 新特性：文档中的二级、三级标题会自动生成 ID。链接到标题 ID 需要使用**两个 `#`**。
  >
  >示例：`<h2>General Principles</h2>` 自动生成 ID `general-principles-heading`。
  >
  >`{@link com.horstmann.corejava.Employee##general-principles-heading}`

- `{@linkplain reference}`：生成普通字体的行内链接，区别于 `{@link}` 的代码等宽字体。

- `{@value optionalFormat constantFieldReference}`：渲染常量字段实际值，自 Java 20 起还支持可选的 printf 格式化器。例如， `{@value%X Integer#MAX_VALUE}` 将生成 7FFFFFFF。

-  `{@snippet}`：[JEP 413](https://openjdk.org/jeps/413)，用于声明在生成的文档中显示的代码片段。它支持语法高亮、外部代码引用等等特性。代码外部文件统一放在当前包的 snippet-files 子目录中

  ```java
  // 导入 snippet-files 目录下的 EmployeeDemo.java 文件
  {@snippet file=EmployeeDemo.java}
  
  // 导入 snippet-files 目录下的 EmployeeDemo.java 文件
  {@snippet class=EmployeeDemo}
  ```

  在外部示例源文件中，可以使用 `@start` / `@end` 标记划定代码区域：

  ```java
  // File: snippet-files/Examples.java
  public class Examples {
      public void show() {
          // @start region="basic-usage"
          Calculator calc = new Calculator();
          int result = calc.add(5, 10);
          // @end region="basic-usage"
      }
  }
  ```

  ```java
  /**
   * Calculates sum.
   * {@snippet class="Examples" region="basic-usage"}
   */
  public int add(int a, int b) {
      return a + b;
  }
  ```

  Snippet 附加修饰标记：

  ```java
  // 按子串高亮
  var e = new Employee();        // @highlight substring=new
  
  // 按正则表达式匹配高亮
  String name = e.getName();     // @highlight regex=get[A-Z][a-z]+
  
  // 正则匹配内容，在文档展示时替换为目标文本
  var e = new Employee("Fred", 100000); // @replace regex=([^)]+) replacement="(..., ...)"
  
  // 为代码片段内指定文本插入Javadoc跳转链接
  var c = new Card(); // @link substring=Card target=com.horstmann.games#Card.<init>()
  ```



在 Javadoc 中，`doc-files` 是一个特殊的目录名称，用来存放无法直接写在代码注释里的杂项文件（如图片、额外的 HTML/Markdown 说明文件），以便在运行 `javadoc` 命令时原封不动地复制到最终生成的文档目录中。

```text
src/
 └── com/
      └── example/
           ├── mypackage/
           │    ├── package-info.java
           │    ├── MyClass.java
           │    └── doc-files/          <-- 放置在此处
           │         ├── overview.html
           │         └── architecture.png
```

```java
/**
 * 模块架构图如下所示：
 * <img src="doc-files/architecture.png" alt="Architecture">
 */
```



## 包

为了更好地组织类，Java 提供了包机制，通过命名空间防止类名冲突，并提供访问权限控制



package 包：

- 包的层级仅为命名约定：编译器不认为嵌套包之间存在任何语义关联。例如，`java.util` 与 `java.util.random` 是两个完全独立的命名空间，各自拥有独立的类集合。
- 若源文件未声明 `package` 语句，其中的类便属于未命名包。其他包无法通过 `import` 导入未命名包中的类。使用未命名包的动机与「紧凑源文件」的一样，都是为了降低学习门槛，提供极简的编写体验。
- 包名与目录结构通常要严格对应：包路径必须映射为相同的文件目录层级；若二者不匹配，在跨包引用时 Java 编译器或类加载器将无法定位类文件。



import 导入：

- 使用通配符 `*` 导入整个包时，只会导入本包中的类。不能使用 `import java.*` 或 `import java.*.*` 来导入所有带有 java 前缀的包

  

## JAR 文件

JAR 包（Java Archive）是 Java 的一种归档文件格式。它本质上是一个 ZIP 压缩文件，把多个 Java 类文件（`.class`）、文本、图片和元数据压缩打包在一起，用来分发、部署和复用程序。

使用 jar 命令来创建 JAR 包，常用选项如下：

- `-c`：创建新 JAR 包

- `-f`：指定 JAR 文件名

- `-v`：显示详细过程

- `-t`： 列出 JAR 包内容

- `-x`：解压 JAR 包

- `-u`：更新现有 JAR 包（添加/替换文件）

- `-m`：指定自定义清单文件

- `-M`：不生成清单文件

- `-e`： 指定可执行 JAR 的入口类

  >可以使用 Launch4j 开源工具来将可执行的 JAR 包封装为 Windows 原生可执行文件 exe

- `-0`：仅归档，不压缩

- `-C`：切换到指定目录后再执行操作

- `-i`： 为 JAR 生成索引文件（`META-INF/INDEX.LIST`）



```bash
# 创建并显示详细过程（将 hello 目录打包）
jar cvf hello.jar hello

# 指定入口类（切换到 bin 目录下，对该目录进行打包，并指定 Main 作为入口类）
jar cvfe app.jar com.example.Main -C bin/ .

# 列出所有文件
jar tf hello.jar

# 解压到当前目录并显示过程
jar xvf hello.jar
```



每个 JAR 文件在 `META-INF/MANIFEST.MF` 中包含一个清单文件，用于描述该 JAR 包的元数据。JVM 和类加载器通过它识别版本、依赖、入口类等信息。

格式规范：

-  UTF-8 编码
- `Key: Value` —— 冒号后必须有一个空格
- 每行不得超过 72 字节；超出需换行，续行必须以单个空格开头
- 必须以一个空行结束（即最后一行是换行符）
- 键名区分大小写

```
Manifest-Version: 1.0
Created-By: 21.0.5 (Oracle Corporation)
Main-Class: com.example.Application
Class-Path: lib/commons-beanutils.jar lib/commons-collections.jar
 lib/commons-digester.jar lib/commons-logging.jar
Implementation-Title: My Application
Implementation-Version: 2.0.0
Implementation-Vendor: Example Corp
```

| 字段                     | 说明                                                 |
| :----------------------- | :--------------------------------------------------- |
| `Manifest-Version`       | 清单文件规范版本，通常为 `1.0`                       |
| `Created-By`             | 生成该 JAR 的工具信息（如 JDK 版本、构建工具）       |
| `Main-Class`             | 可执行 JAR 的入口类全限定名（如 `com.example.Main`） |
| `Class-Path`             | 当前 JAR 包运行所需的其他 JAR 文件                   |
| `Implementation-Title`   | 实现标题                                             |
| `Implementation-Version` | 实现版本号                                           |
| `Implementation-Vendor`  | 实现厂商                                             |
| `Specification-Title`    | 规范标题                                             |
| `Specification-Version`  | 规范版本                                             |
| `Signature-Version`      | JAR 签名版本（签名相关）                             |
| `Sealed`                 | 是否密封包（`true` / `false`）                       |



JAR 包支持**多版本分发**（Multi-Release JAR，MRJAR），允许在同一个 JAR 中打包针对不同 Java 版本的类文件。根目录存放默认版本，特定版本的类文件放在 `META-INF/versions/<N>/` 下：

```
Application.class          ← 默认版本（如 Java 8）
BuildingBlocks.class       ← 默认版本
Util.class                 ← 默认版本
META-INF/
├─ MANIFEST.MF             ← 必须包含：Multi-Release: true
└─ versions/
    ├─ 9/
    │   ├─ Application.class   ← Java 9+ 使用此版本
    │   └─ BuildingBlocks.class
    └─ 10/
        └─ BuildingBlocks.class  ← Java 10+ 使用此版本
```

```bash
# 向已有 JAR 添加版本化类文件
jar uf MyProgram.jar --release 9 Application.class

# 从头构建多版本 JAR, 要为每个版本切换到不同的类文件目录：
jar cf MyProgram.jar -C bin/8 . --release 9 -C bin/9 Application.class

# 在针对不同版本进行编译时，请使用 --release 标志和 -d 标志来指定输出目录
javac -d bin/8 --release 8
javac -d bin/9 --release 9 src/main/java9/Application.java
```

## 模块
