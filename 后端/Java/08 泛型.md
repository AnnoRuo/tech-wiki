# 泛型编程

让代码只需依赖于某种「不具体指定的类型」，而不是某个特定的接口或类，那么就可以编写出更为通用的代码。这便是泛型的概念——**参数化类型**。尽可能让程序员在编写类或方法时拥有尽量丰富的表达力。

在 Java 引入泛型之前，泛型编程通过继承 Object 来间接实现，例如：

```java
public class ArrayList {
  private Object[] elementData;
  
  public Object get(int i) {}
  public void add(Object o) {}
}
```

但这种实现有以下问题：

1. 访问时必须进行强制类型转换

   ```java
   ArrayList files = new ArrayList();
   String filename = (String) files.get(i);
   ```

2. 缺乏编译期错误检查机制，可以添加任何类型的值

   ```java
   files.add(Path.of(". . ."));
   files.add(new File(". . ."));
   ```

现在使用泛型特性编写更加安全的代码，其可以在编译期检查出语法错误。给出一个例子：

```java
ArrayList<Apple> apples = new ArrayList<Apple>();
apples.add(new Orange());							// can only add Orange objects to an ArrayList<Apple>
Apple apple = (Apple)apples.get(0);
```

使用类型推导来简化泛型的编写：

```java
ArrayList<Apple> apples = new ArrayList<Apple>();
ArrayList<Apple> apples2 = new ArrayList<>();
ArrayList<Apple> apples3 = new ArrayList();			// 错误的，必须有<>，否则会被认为是原生类型的
var apple3 = new ArrayList<Apple>();
var apple4 = new ArrayList<>();									// 这会推断出 ArrayList<Object>，不推荐使用
```



术语定义：

- 泛型：语言特性
- 泛型类/泛型方法：泛型的载体
- 类型形参：声明泛型手段
- 泛型类型：实例化泛型类/泛型方法（用具体类型代替类型形参）的产物

## 泛型的基本语法

### 泛型类

```java
// T 是一个类型形参，而 GenericClass<T> 是一个泛型类
class GenericClass<T> {
  private T element;

  public T getElement() {
    return element; 
  }
  
  public static T getElement() {}		//错误的，静态方法不能使用类的泛型参数
}
```

实例化泛型类：

```java
// String 是类型实参，实例化出 GenericClass<String> 泛型类型
GenericClass<String> t = new GenericClass<>();
String s = t.getElement();
```

支持继承泛型类型

```java
class A<T> {
    private T value;
    T get() {
        return value;
    }
}

class B extends A<String> {
    @Override
    String get() {
        return "hello";
    }
    
    @Override
    int get() { return 1; }		// Error,返回类型必须是 String
}
```

### 泛型方法

类型形参在修饰符后，返回类型前

```java
class GenericMethod {
  public static <T> T identity(T t) {
    return t;
  }
  public <T, U> U map(T t) {
      return (U)t;
  }
}
```

调用泛型方法时，通常无需显式给出类型实参——编译器自动推断出类型形参应绑定的具体类型。在极少数需要显式指定类型的情况下，请将类型用尖括号括起来，并直接放在方法名之前：

```java
Collections.<String>emptySet()
```

大量入参场景下类型推断的性能会下降很多。假设您这样调用：

```java
List.of(
    new Pair<>("John", "Smith"),
    new Pair<>("Betty", "Jones"),
    . . .
)
```

当其中包含几百个 `Pair` 时，编译器要推断出所有菱形运算符都应填 `<String>`，所花费的时间会出乎意料地长。如果显式指定类型来帮助编译器，速度会快得多：

```java
List.<Pair<String>>of(
  new Pair<>("John", "Smith"),
  new Pair<>("Betty", "Jones"),
  . . .
)
```

### 泛型与异常

1. 不能 `catch` 类型形参——因为捕获需要具体的类型

   ```java
   try {
     
   } catch (T e) { 	// Error
     
   }
   ```

   

2. Java 语言规范明确禁止泛型类继承 `Throwable`。假设允许继承，那么考虑以下代码

   ```java
   class Problem<T> extends Exception { }
   
   try { ... }
   catch (Problem<String> e) { ... }      // 想捕捉"字符串问题"
   catch (Problem<Integer> e) { ... }     // 想捕捉"整数问题"
   ```

   两个 catch 擦除后完全相同，编译器无法确定应该匹配哪个。因此就禁止这种行为

3. 虽然不能捕获 `T`，但声明抛出 `T` 是合法的：

   ```java
   interface Task<T extends Throwable> {
   	void run() throws T;
   }
   ```

   ```java
   <T extends Throwable> void repeat(Task<T> t, int n) throws T {
     for (int i = 0; i < n; i++) t.run();
   }
   
   public void test() {
     try {
       // 这里 Thread.sleep 所抛出的异常 InterruptedException 作为 T 的类型实参
       repeat(() -> Thread.sleep(1), 10);
     } catch (InterruptedException e) {
   
     }
   
     try {
       // 由于 System.out.println 未抛出任何受检异常，由于就推断 T 为 RuntimeException
       repeat(() -> System.out.println("1"), 10);
     } catch (RuntimeException e) {
   
     }
   }
   ```

   

   下面介绍一种技术——Sneaky throw，允许在 Java 中绕过编译器检查、无需在方法签名中显式声明 `throws` 或编写 `try-catch` 块就能直接抛出受检异常，就像 RuntimeException 行为一样。

   ```java
   public class SneakyThrowDemo {
     @SneakyThrows
     public void test2() {
       SneakyThrowDemo sneakyThrowDemo = SneakyThrowDemo.class.newInstance();
     }
   
     // test2方法的编译结果
     public void test3() {
       try {
         SneakyThrowDemo sneakyThrowDemo = SneakyThrowDemo.class.newInstance();
       } catch (Throwable e) {
         // 调用Lombok方法转化为RuntimeException
         throw Lombok.sneakyThrow(e);
       }
     }
   }
   ```

   Lombok.sneakyThrow 的实现

   ```java
   
   public static RuntimeException sneakyThrow(Throwable t) {
     if (t == null) throw new NullPointerException("t");
     // 编译器认为这里的 t 就是 RuntimeException 类型
     return Lombok.<RuntimeException>sneakyThrow0(t);
   }
   
   public static <T extends Throwable> void rethrow(Throwable t) throws T {
     // (T) 的转换不可验证，编译器只能默认信任，以为 T 为类型实参
     throw (T) t;    
   }
   ```

### 泛型数组

在 Java 中禁止 new 泛型数组（泛型实参的数组或泛型形参的数组）

```java
List<String>[] list2 = new List<String>[10];  // 编译错误：generic array creation
T[] arr2 = new T[10];                          // 编译错误：generic array creation
```

这是由于数组与泛型这两套机制的根本矛盾：

- 数组：

  - 协变（covariant）：如果 `Sub` 是 `Super` 的子类，那么 `Sub[]` 也是 `Super[]` 的子类。`String[]` 可以直接赋值给 `Object[]`

  - 具体化：数组在运行时保存了类型信息，并且每次写入时都会做类型检查：

    ```java
    Object[] objs = new String[10];
    objs[0] = Integer.valueOf(42);  // 运行时抛 ArrayStoreException
    ```

- 泛型：

  - 不变（invariant）：`List<String>` 和 `List<Object>` 之间没有任何继承关系。不能相互赋值
  - 擦除：泛型的类型实参只存在于编译期。`List<String>` 编译后就是 `List`。类型检查全部由编译器在编译期完成

数组的安全依赖运行时检查，而泛型的类型信息在运行时不存在。假如 `new List<String>[10]` 合法：

```java
List<String>[] stringLists = new List<String>[10];  // 假设合法
Object[] objs = stringLists;                        // 数组协变，List 是 Object 的子类型
objs[0] = new ArrayList<Integer>();                 // objs 底层类型是 List，由于 Integer 以及 String 都被擦除掉了，这里传入 ArrayList 子类型是合法的
String s = stringLists[0].get(0);                   // ClassCastException 在这里爆炸 🤯，造成堆污染（heap pollution）问题
```

这破坏了泛型的核心承诺，只要编译没有 unchecked 警告，运行期就不会出现 ClassCastException。



虽然禁止 new 泛型数组，但是可以声明它们，这是因为声明变量本身不产生任何运行时对象，也就没有堆污染的实际风险。

```java
List<String>[] lists;  // 合法
T[] lists;						 // 合法
```

此外，可具体化类型（Reifiable Types）中无界通配符的是允许创建泛型数组的，但它有着诸多语法限制，等会我们会看到。

```java
List<?>[] lists = new List<?>[10];  // 合法, List<?> 是可具体化类型
```

>可具体化类型（Reifiable Types）是指在运行时其类型信息完整保留、完全可用的类型，不会在编译时被擦除。包括以下类型：
>
>- 基本类型（Primitive Types）：如 `int`、`double`、`boolean` 等。
>- 非泛型类型（Non-generic Types）：如类或接口。
>- 原始类型（Raw Types）：如不带泛型参数的 `List`、`Map` 等
>- 无界通配符调用（Unbounded Wildcard Parameterized Types）：如 `List<?>` 或 `Map<?, ?>`
>
>以下类型是不可具体化的：
>
>- 类型形参，如 T
>- 具有类型实参的参数化类型，如`List<String>`，`Map<String, Integer>`
>- 有界限的参数化类型，如 `Comparable<? super String>`， `List<? extends Number>`



我们可以通过以下手段来间接创建泛型数组。总结来说，泛型数组在擦除的设计前提下无法保证类型安全，所以语言选择禁止创建、把风险显式交还给程序员 `@SuppressWarnings("unchecked")` + 强制类型转换：

1. 无界通配符数组：

   ```java
   List<?>[] lists = new List<?>[10];
   lists[0] = new ArrayList<String>();   // 合法
   lists[1] = new ArrayList<Integer>();  // 合法
   lists[0].add("x");                    // 编译错误，List<?> 不能写
   String s1 = lists[0].get(0);          // 编译错误，无法读出 String 类型
   Object s2 = lists[0].get(0);          // 只能读出 capture of ?
   
   
   // 这里就向编译器保证类型安全由程序员自己负责
   @SuppressWarnings("unchecked")
   List<String>[] lists = (List<String>[]) new List<?>[10];
   Object[] objs = lists;
   objs[0] = new ArrayList<Integer>();  // 自己打开了协变的口子
   String s = lists[0].get(0);          // 又炸了，哈哈，活该 😄
   ```

2. 在Object[] 向泛型数组 T[] 进行强制类型转换（T[] -> Object[] 转换不用强制）

   ```java
   public MyStack(int capacity) {
     @SuppressWarnings("unchecked")
     this.elements = (E[]) new Object[capacity];  // 间接创建
   }
   ```

3. 使用 ArrayList（推荐）

   ```java
   List<String>[] strListArr = new List<String>[10];		//Error
   ArrayList<List<String>> sttListArr = new ArrayList<>();
   
   T[] array = new T[];																//Error
   ArrayList<T> array = new ArrayList<>();
   ```

4. 泛型可变参数，`T...` 的本质就是编译器帮你 new 了一个泛型数组（官方特批）。此时编译器会报出警告 `Possible heap pollution from parameterized vararg type`，我们可以用 `@SafeVarargs` 来抑制警告，它向编译器保证方法内只读取可变参数并不会修改它们

   ```java
   @SafeVarargs
   public static <T> void printAll(T... items) {
   
   }
   ```

   

## 类型擦除与翻译

事实上，对于泛型的翻译有两种策略：

- **同构翻译（homogeneous translation）**：一个所有类型共享一种实现
- **异构翻译heterogeneous translation）**：一个为每种类型组合都创建一份特化

C++ 和Java 的策略分别处于异构翻译和同构翻译的极端。而 C#/CLR 处于两者中间，即为共享布局的引用类型同构翻译，为值类型异构翻译。

同构翻译带来的类型擦除问题：

- 擦除后字节码中无泛型参数的信息，因此无法获取泛型参数的具体值

- 运行时类型检查，`List<String>` 会被擦除为 `List`，所以当通过一些手段（强制转换，raw type 等）将其他类型的值放入这个 List 的时候并不会出错，直到实际访问时才会发生问题。

- 同构翻译要求泛型参数类型必须拥有「公共运行时表示」（common runtime representation），在 Java  里这意味着只能是一组引用类型，而不能为原始类型。这导致我们只能用 `List<Integer>`，而用不了针对 `int` 进行布局特化的 `List<int>`，底层存放的全是对 `Integer` 对象的引用，这造成了巨大的内存浪费，同时对现代 CPU 的缓存策略极端不友好。这是 Java 泛型擦除最大的问题。

  目前  OpenJDK 的 Project Valhalla 项目正孵化出布局特化，或许将来某个时候，我们可以声明 `ArrayList<int>` 了

当然异构翻译也有一些问题：

- 模板的每个实例都要有着不同的代码，这意味着模板展开会导致代码膨胀。产生更大的硬盘和内存占用

类型擦除的优势：

- **兼容性**。它完全维护了二进制兼容性和源代码兼容性。不会因引入泛型后让社区生态产生巨大的分歧
- **类型系统的自由度**：虽然 Java 和 JVM 常常被绑定在一起，但它们是各自独立的，有着各自的规范。得以让 Scala 在 JVM 上实现一套表达力远超 Java 的类型系统，同时又与 Java 泛型保持高度的二进制互操作性。



获取泛型参数具体值的间接手段：

1. TypeReference 模式：利用「类签名中仍然保留着泛型信息」的特性来获取泛型参数的具体值：

   ```java
   class Foo {
     // 泛型信息存在字段签名里
     List<String> names;
   }
   
   Field f = Foo.class.getDeclaredField("names");
   ParameterizedType pt = (ParameterizedType) f.getGenericType();
   Type arg = pt.getActualTypeArguments()[0];   // -> class java.lang.String
   ```

   ```java
   // 原理：匿名类会生成 superType，其 Signature 中记录了实际类型参数
   TypeToken<List<String>> token = new TypeToken<List<String>>() {};
   Type t = token.getType();   // java.util.List<java.lang.String>
   ```

2. 显式传入 Class 对象

   ```java
   class Repository<T> {
       private final Class<T> type;
       Repository(Class<T> type) { this.type = type; }
   }
   
   new Repository<>(User.class);
   ```

## 类型边界

类型边界（bound）让你在使用泛型时，可以为类型形参添加约束：声明 `T extends SomeType` 之后，编译器就知道 `T` 至少是 `SomeType` 的子类型，从而允许你在泛型代码中直接调用 `SomeType` 上定义的方法。类型边界可以是**多重的**，但其中只能有一个具体类，而且具体类（如果有的话）必须放在最前面，不过可以有任意个接口：

```java
class WithColor<T extends HasColor> {}
class WithColorCoord<T extends Coord & HasColor>
```

无界的类型形参被擦除为 `Object`。而有界的类型形参被擦除为其最左边的边界，并且在必要时编译器会强制类型转换为其他边界类型。
